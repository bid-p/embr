# embr

General purpose embedded library with a focus on robotics, built on top of [modm](https://modm.io).

embr is an [lbuild](https://github.com/modm-io/lbuild) repository that sits alongside modm's. A
project lists both repositories in one `project.xml`, picks its target and modm modules directly,
and adds the embr modules it wants. embr modules declare the modm modules they depend on, so lbuild
pulls those in automatically.

```xml
<library>
    <repositories>
        <repository><path>../embr/modm/repo.lb</path></repository>
        <repository><path>../embr/repo.lb</path></repository>
    </repositories>
    <options>
        <option name="modm:build:project.name">my-project</option>
        <option name="modm:build:scons:include_sconstruct">False</option>
        <option name="modm:target">stm32g431rbt6</option>
    </options>
    <modules>
        <module>modm:platform:gpio</module>
        <module>embr:core</module>
    </modules>
</library>
```

Running `lbuild build` generates:

- `modm/` and `embr/`, each with an `SConscript` (generated by `modm:build:scons`) that builds a
  static library
- `Sconstruct` and `build_tools/` (from `embr:build-tools`), which build the application in `src/`
  against those libraries

Then `scons build`, `scons size`, `scons run`, or `scons gdb`.

## Requirements

- Python with `lbuild` and `scons`
- An `arm-none-eabi` toolchain supported by modm: GCC 13 or 14 (modm recommends 14). Tested with
  Arm GNU Toolchain 14.3.rel1.
  - GCC 15 compiles but fails to link: modm's `AdcChannel`/`DacChannel` specializations in
    `modm/platform/gpio/data.hpp` produce "multiple definition" errors. This is still the case
    in modm 2026q2.
  - Older toolchains lack `-std=c++23` (GNU Arm Embedded 10.3) or binutils 2.39+ for
    `--no-warn-rwx-segment` (the GCC 11.3 bundled with STM32CubeIDE 1.13).

## Modules

| Module              | Description                                                        |
| ------------------- | ------------------------------------------------------------------ |
| `embr:core`         | Umbrella module that pulls in everything below                     |
| `embr:build-tools`  | Project `Sconstruct` and argument parsing                          |
| `embr:time`         | Millisecond/microsecond clock accessors, `Timeout`, `PeriodicTimer` |

## Adding a module

Create a `module.lb` under `src/`, depend on the modm modules it uses, copy its files under
`embr/src/emlib/`, and register the include path:

```python
def prepare(module, options):
    module.depends("modm:platform:uart")
    return True

def build(env):
    env.outbasepath = "embr/src/emlib/<area>"
    env.copy("<file>.hpp")
    env.collect("modm:build:path.include", "embr/src")
```
